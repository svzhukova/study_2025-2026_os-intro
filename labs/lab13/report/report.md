# Цель работы

Приобретение навыков настройки сервера NFS для удалённого доступа к ресурсам.

# Задание
1. Установите и настройте сервер NFSv4 (см. раздел 13.4.1).
2. Подмонтируйте удалённый ресурс на клиенте (см. раздел 13.4.2).
3. Подключите каталог с контентом веб-сервера к дереву NFS (см. раздел 13.4.3).
4. Подключите каталог для удалённой работы вашего пользователя к дереву NFS (см.
раздел 13.4.4).
5. Напишите скрипты для Vagrant, фиксирующие действия по установке и настрой-
ке сервера NFSv4 во внутреннем окружении виртуальных машин server и client.
Соответствующим образом внесите изменения в Vagrantfile (см. раздел 13.4.5).

**Монтирование NFS на клиенте** 

На клиенте создадим каталог, в который будет монтироваться удалённый ресурс,
и подмонтируем дерево NFS, проверим, что общий ресурс NFS подключён правильно (рис. [-@fig:008]).

![Подключен](image/8.png){#fig:008 width=70%}

server.svzhukova.net:/srv/nfs - источник: удалённый сервер и экспортируемый на нём каталог.
on /mnt/nfs - точка монтирования на клиенте: содержимое /srv/nfs сервера отображается в этом каталоге.
type nfs4 - тип файловой системы, сетевая файловая система NFS версии 4.
ro - монтирование только для чтения, это следует из параметра ro в /etc/exports на сервере.
relatime - время последнего доступа к файлам обновляется не при каждом чтении, а выборочно.
vers=4.2 - используемая версия протокола NFS (договаривается с сервером).
rsize=262144,wsize=262144 - размеры блоков чтения и записи в байтах при передаче по сети.
namlen=255 - максимальная длина имени файла.
hard - при недоступности сервера клиент продолжает повторять запросы, а не завершает их ошибкой.
proto=tcp - транспортный протокол TCP (порт 2049).
timeo=600,retrans=2 - таймаут запроса в десятых долях секунды (60 с) и число повторов до сообщения об ошибке.
sec=sys - способ аутентификации по идентификаторам пользователя и группы (UID/GID) клиента.
clientaddr=192.168.1.2 и addr=192.168.1.1 - адрес клиента и адрес сервера.
local_lock=none - блокировки файлов обрабатывает сервер.

Удалённый каталог /srv/nfs сервера успешно подключён к клиенту в /mnt/nfs по протоколу NFSv4 только для чтения.

На клиенте в конце файла /etc/fstab добавим следующую запись  (рис. [-@fig:009]).


![Запись](image/9.png){#fig:009 width=70%}

server.svzhukova.net:/srv/nfs /mnt/nfs nfs _netdev 0 0: в /etc/fstab каждая строка описывает одну файловую систему и состоит из шести полей, разделённых пробелами.

server.svzhukova.net:/srv/nfs - что монтировать: сервер и экспортируемый на нём каталог в формате хост:путь.
/mnt/nfs - куда монтировать: точка монтирования на клиенте, каталог должен существовать.
nfs - тип файловой системы. Для NFS указывается nfs, версия протокола (4.2) согласуется автоматически.
_netdev - параметры монтирования. Этот параметр сообщает системе, что устройство сетевое. Монтирование выполняется только после запуска сети, иначе при загрузке клиент пытался бы подключить ресурс до появления сети, и загрузка затягивалась бы или завершалась ошибкой.
0 - флаг для утилиты dump (резервное копирование): 0 означает, что копировать не нужно.
0 - порядок проверки файловой системы утилитой fsck при загрузке: 0 означает, что проверка не выполняется (для сетевых ресурсов она не нужна)

# Контрольные вопросы


1. Как называется файл конфигурации, содержащий общие ресурсы NFS?
/etc/exports. В нём перечисляются экспортируемые каталоги, клиенты, которым они доступны, и параметры доступа, например /srv/nfs *(ro). Дополнительные описания можно размещать в файлах *.exports в каталоге /etc/exports.d/. После изменений список обновляют командой exportfs -ra, а текущие экспорты смотрят командой exportfs -v.

2. Какие порты должны быть открыты в брандмауэре для полного доступа к серверу NFS?

Для NFSv4: TCP-порт 2049. В firewalld его открывает служба nfs: firewall-cmd --add-service=nfs --permanent.
Для NFSv3 и команды showmount дополнительно нужны порт 111 (TCP и UDP, служба rpcbind) и порт 20048 (служба mountd): firewall-cmd --add-service=mountd --add-service=rpc-bind --permanent.

В лабораторной работе одной службы nfs хватило для монтирования ресурса, а для showmount пришлось бы открывать остальные, поэтому он и не работал при включённом экране.

3. Какую опцию следует использовать в /etc/fstab, чтобы общие ресурсы NFS монтировались автоматически при перезагрузке?
Опцию _netdev. Она сообщает системе, что устройство сетевое, и монтирование выполняется только после запуска сети, иначе при загрузке клиент пытался бы подключить ресурс до появления сети. Пример записи: server.svzhukova.net:/srv/nfs /mnt/nfs nfs _netdev 0 0. Дополнительно используют nofail, чтобы загрузка клиента не прерывалась, если сервер недоступен.
